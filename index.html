How this measurement works

Every engine draws one 122 × 122 gear on a 640 × 360 WebGL canvas at resolution 1 with antialiasing. The gear is a webp data URL inside each bundle, loaded through the engine's own image loader, so the page makes no asset request: what is measured is navigation, script download and parse, engine boot, one image decode and texture upload, and the first frame. Each engine reports from its own render loop after that frame; a shared hook then waits for the render stack to return and calls WebGL finish(), so GPU completion is included. Physical screen presentation is not.

Each sample runs in a fresh browser process with an empty HTTP cache and service workers blocked, so code, images and shaders load every time. A blank WebGL page runs first so GPU process start-up is excluded, as in an already-open browser. Engine order rotates each round. OS, DNS and GPU driver caches are not reset.

Network profiles apply bandwidth and latency limits through Chromium DevTools; CPU is not throttled. Responses are gzipped. With no asset requests, throttled profiles mostly reflect bundle size.

How this measurement works

Every engine fetches the same packed atlas, a 1204 × 1918 webp (3.5 MB) plus its JSON, and draws both 1200 px paintings at quarter size on a 640 × 360 WebGL canvas at resolution 1 with antialiasing. Bare keeps its standard bootstrap: the built page preloads the atlas from <link rel=preload> tags in parallel with its script. The others use their native atlas loaders, which start the requests once their script has run. On top of the first benchmark this adds the atlas requests, a large webp decode and a 9 MB texture upload. Each engine reports from its own render loop after the first frame with both paintings; a shared hook then waits for the render stack to return and calls WebGL finish(), so GPU completion is included. Physical screen presentation is not.

Each sample runs in a fresh browser process with an empty HTTP cache and service workers blocked, so code, images and shaders load every time. A blank WebGL page runs first so GPU process start-up is excluded, as in an already-open browser. Engine order rotates each round. OS, DNS and GPU driver caches are not reset.

Network profiles apply bandwidth and latency limits through Chromium DevTools; CPU is not throttled. Responses are gzipped (the webp is not compressible). Unthrottled on localhost, requests are nearly free, so the engines differ mostly in boot, decode and upload; throttled profiles expose the request waterfall, which is where parallel preloading matters.
